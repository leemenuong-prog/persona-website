问题 · The Gap

一个开发团队，
填不满全公司的
Agent 需求

这是 XTOOL 实习时的真实观察：业务侧的自动化需求源源不断，开发排期永远追不上。 要让 Agent 普及，门槛必须从「描述 AI」降到「做一遍」。

传统 · Prompt-first

先把工作，压缩成一句话。

一句 Prompt 能描述想要的结果, 却说不清工作里的步骤、数据来源与判断——目标说出来了，过程仍然埋在经验里。

Pears · Watch-first

让用户像平时一样，把任务做一遍。

在真实操作中理解工作如何发生, 把隐性经验沉淀为真正可用、可持续优化的 Agent。

方案 · The Factory

「观察 → 生成 → 强化」的 Agent 工厂

STEP 1

观察

在你明确开启的任务会话里，像平时一样把工作做一遍，过程被自动记录。

STEP 2

蒸馏 PRD

行为轨迹被整理成一份可编辑的 PRD：步骤、数据来源、判断口径，都摆到明面上。

STEP 3

生成 Agent

AI 编码 Agent 按 PRD 搭建你专属的 Workflow Agent，生成可运行的构建包。

STEP 4

强化

每次交付都能回看、比较与修改——Agent 沿着你的真实使用持续优化。

02 — XTOOL · Agent 平台

判断 · The Call

高创意内容，无法一次成型

数据说明流失在哪，判断决定怎么改: LLM 一次生成撑不起高创意内容。方子是合并生成阶段、三候选并出——让人挑，而不是让人等。这个判断推动了三代产品迭代。

GEN 1

单链路生成

一次出一稿，反复重跑。创意质量不稳定，等待成本高。

GEN 2

阶段合并

把拆散的生成阶段合并，减少中间等待与信息损耗。

GEN 3

三候选并出

同批三个候选并排给人挑——把「等 AI」变成「选方案」。

03 — 议见 · Consensus Engine
02 / 04
问题 → 机制

会开完了，
决策呢

选品、预算加码、区域首发——企业里最贵的动作是拍板, 可会议留下的常常只有：意见多、共识难、事后说不清当时为什么这么定。 议见的答案：分歧不是压下去，是分四层算清楚。

意见多 / 共识难 / 不可追溯 → L1–L4 逐层收敛

L1

战略目标

这个决策服务哪个目标?目标之间冲突吗?

L2

事实证据

支撑判断的数据可靠吗?缺口在哪?

L3

利益角色

谁受益、谁承压?立场差异摆上桌面。

L4

权重权责

谁对结果负责，谁的意见就有对应权重。

02 / 04
Pipeline · The System

非标展品，进来；标准化资产，出去

50+ 件展品来自不同作者、不同格式、不同完成度。 这条工作流让处理周期从 30 天压到 5 天——效率不是目的，它让 120+ 次迭代成为可能，统一的视觉宇宙才打磨得出来。

IN

展品资料

图纸、照片、文本——非标输入。

GEMINI

语义解析

提取展品的形态与叙事要素。

COMFYUI

图像生成

统一视觉宇宙下的概念图与分镜帧。

TRIPO

3D 生成

图像升维为可用的三维资产。

SOP

标准化出品

命名、精度、格式统一收口。

30 天 → 5 天 单件展品处理周期
50+ 非标展品完成转译
120+ 草图与模型迭代
